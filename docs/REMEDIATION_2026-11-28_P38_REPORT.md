## 3. The closure verdict (the headline)

**The credit note can finally ride the channel the pipeline built for it — from a browser that always advertised the trip.** P34 built the credit-note pipeline, P35 added its business rules, P36 its arithmetic, P37 its reference truth — and P38's audit found the workflow layer still holding the pre-P34 ticket: `send_invoicenow`'s P9/C-3 gate refused the type (calibrated when accepting a credit note would have transmitted a hollow document), the approval auto-transmit never fired for it, and the UI's Send-via-InvoiceNow button rendered on APPROVED credit notes and always 400'd. Worse, the sprint's own live contract re-verification (seeding the demo org's Peppol settings to prove the 200) exposed the deeper break: the Celery app never loaded in the web process — every WSGI-process task dispatch hit Celery's default amqp app and 500'd on the first real send (masked until now because no configured org had ever dispatched and every test mocks `.delay`). Post-P38 both gates carry the outbound transmittable set {SALES_INVOICE, SALES_CREDIT_NOTE} — quotes and inbound types still refused, their hazard being type-semantic and permanent — and the canonical `config/__init__.py` import loads the configured app in every Django process. Proven live end to end: the real demo credit note queues 200/QUEUED with a pollable log row, the DRAFT and quote controls still refuse with their documented messages, and the credit-note detail page's button is finally honest.
