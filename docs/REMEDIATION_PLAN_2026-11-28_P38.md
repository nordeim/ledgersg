## 2. Findings (verified, with evidence anchors)

### High

**BE-P38-H2 — the Celery app never loads in the web process: every real task dispatch from a request hits Celery's default app (amqp broker, eager off) and 500s.**

The canonical fix (Celery's "First steps with Django", the pattern the docs themselves prescribe): `config/__init__.py` gains the app import so the Django process — runserver, gunicorn, wsgi — loads the configured app at startup and every `@shared_task` binds to it:

```python
from .celery import app as celery_app
__all__ = ("celery_app",)
```

With it, the web process's `queue_task` dispatches to `redis://localhost:6379/0` (the configured broker — `base.py:273`, from `REDIS_URL`) and honours `CELERY_TASK_ALWAYS_EAGER` (dev/testing inline execution — the documented dev contract; production stays async through the real worker). Without it, the first dispatch on any Peppol-configured org 500s (reproduced live this session).

**BE-P38-H1 — the credit-note InvoiceNow transmission is workflow-blocked on both entry paths while the UI advertises it and the pipeline is fully built.**

Every outbound document the PINT-SG pipeline can render should be transmittable through the workflow that owns it. The fix opens the two gates to the outbound transmittable set — and ONLY that set:

- **`send_invoicenow` (document_service.py:1240):** the type gate widens from `!= "SALES_INVOICE"` to `not in ("SALES_INVOICE", "SALES_CREDIT_NOTE")`; the error message names both accepted types. The downstream pipeline is type-aware end-to-end (the generator + the validator dispatch by root; BR-SG-07 is sound because the DB layer enforces `related_document_id` on every credit note — P14/H-4 — so a service-created credit note always carries the reference the Schematron floor demands). The quote refusal (P9/C-3's actual target — an APPROVED quote rendered as a tax invoice) and the inbound-type refusal (PURCHASE_* — documents this org RECEIVES, not sends) both stay exactly as they are.
- **`approve_document` (document_service.py:967):** the auto-transmit queue condition widens from `== "SALES_INVOICE"` to `in ("SALES_INVOICE", "SALES_CREDIT_NOTE")`. `_queue_peppol_transmission` itself is type-agnostic (settings → auto_transmit → contact peppol_id → log + task — verified in source); only its docstring says "must be SALES_INVOICE" (updated) and the caller gates.
- **The frontend needs NO change:** `canSendInvoiceNow` already renders for APPROVED non-quote documents — post-P38 the button simply succeeds for credit notes (the toast copy "The invoice has been queued…" is generic enough; the P37 precedent — the web tree renders whatever the API sends — holds).
