## 2. Findings (verified, with evidence anchors)

### High

**BE-P35-H1 — the Schematron business-rule truth: the layer above the now-real XSD is decorative (triple defect, all reproduced).**
Three concrete harms:
1. **The artefact is broken** — the wrong namespace + an unsupported query binding mean the `.sch` has never been loadable by any ISO-Schematron implementation; nothing downstream could ever have used it.
2. **The wiring is absent** — `_validate_schematron` is a never-called placeholder returning `[]`; `schematron_errors` is a constant empty list in every validation result; the vacuous test pins nothing. The cross-element business truths the XSD cannot express (the P33 currency-consistency thread: every amount's `currencyID` must equal `DocumentCurrencyCode`) are unvalidated — proven by the tampered-currency probe passing clean.
3. **The division of labour is undocumented** — the XSD (post-P34) enforces STRUCTURE; the business-rule layer (PINT-SG BR-* rules) is the layer real Peppol access points add on top. Without it, LedgerSG's validation verdict overstates what was checked.

**Fix (three seams, one truth):**
- **(a) `PINT-UBL-validation.sch` corrected and upgraded:** the true ISO Schematron namespace (`http://purl.oclc.org/dsdl/schematron`), `queryBinding="xslt"` (the binding lxml's skeleton supports — XPath 1.0), all FOUR namespace bindings (Invoice-2, CreditNote-2, cac, cbc), and a rule set that is deterministic under XPath 1.0: the root must be Invoice or CreditNote; the document must carry `cbc:ID` and `cbc:IssueDate`; `cbc:DocumentCurrencyCode` must match `[A-Z]{3}` (the ISO-4217 shape — the vocabulary itself lives at the input surfaces, P34/M1); **every amount element's `currencyID` must equal `DocumentCurrencyCode`** (the flagship cross-element rule pinning the P33 truth — TaxAmount, TaxableAmount, LineExtensionAmount, TaxExclusiveAmount, TaxInclusiveAmount, PayableAmount, PrepaidAmount, PriceAmount); the document must carry at least one line (the BR-08 analog; the XSD enforces it too — the business floor is deliberate redundancy).
- **(b) `_validate_schematron` wired and real:** loaded in `__init__` beside the XSDs (the hardened parser, P14/X-1 posture) with the **fail-closed load posture** (mirroring the P9/S-3 XSD contract: a `.sch` that fails to load reports an error, never silence); called by BOTH `validate_invoice_xml` and `validate_credit_note_xml`; populates `schematron_errors` from the SVRL failed-asserts (message + location); `is_valid` folds BOTH error lists.
- **(c) The vacuous test retired:** `test_validate_returns_schematron_errors` upgraded from `assert ... or True` to real assertions on the wired behavior.

**BE-P35-H2 — the transmission failure-path truth: the error-join crashes on the real validator shape.**
`"; ".join(errors)` TypeErrors on the list-of-dicts the real validator returns; the outer `except Exception` converts a `VALIDATION_ERROR` into an `INTERNAL_ERROR` carrying a Python TypeError string. **Fix:** a shape-tolerant message formatter at the seam (dicts → their `message` values; strings pass through; anything else → `str()`) — the typed VALIDATION_ERROR code with the joined REAL messages, plus a REAL transmission spec that feeds a genuinely schema-invalid document through `_execute_transmission` (no validation mock) and asserts the failure code + the real message text. The existing string-shaped mocks keep passing (the formatter is tolerant by design).

## 6. Open decisions (resolved with judgment)

- **The `xslt` query binding (XPath 1.0), not `xslt2`:** the repo artefact declared `queryBinding="xslt2"`, but an XSLT 2.0 binding requires a Saxon processor the stack does not carry; lxml's `isoschematron` ships the XSLT 1.0 skeleton. Every rule in the chosen set is deterministic under XPath 1.0; the arithmetic rules that genuinely need stronger semantics are REGISTERED, not faked (§4).
- **The rule set = the cross-element truths + the business floors, not a full PINT-SG BR-* transcription:** the structural truth is the XSD's job (P34); the Schematron layer carries what the XSD cannot express — the amount-currencyID consistency sweep (the P33 truth), the currency-code shape, the root-type and presence floors. A full transcription (100+ rules) would be mostly redundant with the XSD and unmaintainable by hand; the five-rule set is honest, deterministic, and each rule is pinned by a spec. The ISO-4217 VOCABULARY check stays at the input surfaces (P34/M1) — a Schematron regex on the code list would duplicate the allowlist in an untestable artefact.
- **The fail-closed load posture mirrors P9/S-3:** a `.sch` that fails to load reports an error in `schematron_errors` and flips `is_valid` to False — identical to the XSD None-schema contract already pinned by `test_none_schema_reports_an_error_not_silence`. Consistency of posture beats per-layer special cases.
- **`is_valid` folds BOTH error lists:** a document that passes the XSD but fails a business rule is NOT valid — the transmission must not send it. The transmission service's existing `schema_errors or schematron_errors or errors` chain already surfaces schematron errors exactly when the schema passes (the new failure mode), so NO transmission-side read change is needed for the gating — only the join formatting (H2).
- **The shape-tolerant formatter (not a shape migration):** rewriting the validator's error dicts to strings would break the P10/M-4 detail contract (line/column in the API surface where exposed) and the existing pins; tolerating both shapes at the join seam fixes the crash without touching any published shape.
- **The SVRL message shape `{"message": ..., "location": ...}`:** the SVRL report carries an XPath location, not line/column; the dict shape stays join-compatible via the formatter (H2). No `line`/`column` fabrication.
- **No new e2e spec:** the business-rule truth is XML-level (pinned by the new backend specs); the failure-path truth is a service-level contract (pinned by the real transmission spec). The browser surfaces render whatever the API sends.
- **The UP batch / E501 + format axis / N818 / mypy gate stay out (again):** the registered preconditions are unchanged.
