## 3. The wiring verdict (the headline)

**Every list surface in the web app now pages server-side, and the last unbounded backend list carries the contract.** The P24 sprint paginated the backend and wired the ledger; the P25 sprint hardened the contract; this sprint closed the loop: the invoices, contacts, payments, bank-transactions and quotes pages were still fetching their entire history in one response (the invoices search filtered client-side over only the fetched rows — a silent lie at any real volume; the contacts hook discarded the envelope so a total was structurally unrenderable; the payments list carried a comment confessing its dead Load-more since P10). All five surfaces now page at size 20 through the shared, a11y-hardened `TablePagination`, every hook carries the page identity in its queryKey (the cache-paging trap pinned per hook), the invoices search goes server-side, and the Peppol transmission log (org-wide, one row per send/retry) joined the `?limit=&offset=` contract with the `id` tiebreaker and a single conditional-aggregation counters query. The e2e contract follows the P25 lesson's stronger form: the new spec stocks its own fodder through the public API (DRAFT documents post no journal lines — the F5 boxes and dashboard stay untouched), and the fresh-DB proof verifies the self-sufficiency: one bootstrap, first run, **43/43 with 0 skipped**.
