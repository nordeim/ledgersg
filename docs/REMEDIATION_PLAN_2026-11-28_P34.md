## 2. Findings (verified, with evidence anchors)

### High

**BE-P34-H1 — the credit-note Peppol truth: the SALES_CREDIT_NOTE InvoiceNow path has never been able to transmit a meaningful document (triple defect, all reproduced).**
Three concrete harms:
1. **The transmitted document is hollow** — no supplier/customer parties, no tax or monetary totals, no lines; a Peppol access point validating PINT-SG rejects or mis-renders it.
2. **The path is structurally broken** — the transmission service validates the CreditNote root against the Invoice XSD, so the transmission is marked FAILED (schema errors) before the AP is ever called; the credit-note path can never succeed even by accident.
3. **The dedicated validator is equally broken** — the CreditNote XSD's Invoice-2 targetNamespace rejects the generator's CreditNote-2 output, so fixing the wiring alone would not close it.

**MID-SPRINT DISCOVERY (the TDD RED gate caught it — recorded 2026-11-28, plan amended before the report): the defect class is one level deeper than scoped.** While turning the acceptance gate GREEN, the generated INVOICE also failed the Invoice XSD — the validation layer was **decorative for BOTH paths**: the single-file XSDs declared the header children and aggregates as LOCAL elements in each root's target namespace while the generator (correctly, per real UBL 2.1) emits them in the `cbc:`/`cac:` namespaces, AND the amount attributes (`currencyID`, `unitCode`, `schemeID`) were never declared at all (0 attribute declarations in both XSDs — any document carrying them failed). Every generated document, invoice or credit note, failed validation; on the real transmission path every transmission would be marked FAILED before reaching the access point. The suite never saw it for the same stacked-blind-spot reason. **The fix scope expanded accordingly** (the root cause, not the symptom): both XSDs restructured into the true three-namespace UBL shape — a NEW `ubl-CommonBasicComponents-2.xsd` (the basic-component globals with the AmountType 14,4 precision, the amount attributes `currencyID` use="required", the quantity `unitCode`, the `schemeID` attributes) + a NEW `ubl-CommonAggregateComponents-2.xsd` (the aggregate globals: parties, tax totals, monetary total, the lines) + both root XSDs rewritten as ref-based sequencers declaring the PINT-SG required-structure contract. The old XSDs' TaxCategoryIDType enum moved out of XSD reach (the tax-category ID is `cbc:ID`, a shared global — the vocabulary truth lives in the mapper's DB-driven tax codes); the structurally-wrong string-typed `PayeeFinancialAccount` child was dropped (never emitted). A NEW invoice-side acceptance gate pins the fix symmetrically.

**Fix (four seams, one truth):**
- **(a)** `generate_credit_note_xml` emits the full document, mirroring `generate_invoice_xml`: `DueDate` (after IssueDate, before the type code), the supplier/customer parties, the payment terms, the tax total, the legal monetary total, and the lines — via a NEW `_create_credit_note_line` helper (the UBL 2.1 CreditNote line: `cac:CreditNoteLine` + `cbc:CreditedQuantity`, mirroring `_create_invoice_line`'s ID/quantity/LineExtensionAmount/Item/Price shape). The P33 currency parameter threads through every amount-creating helper exactly as on the invoice path (`currency = mapped_data.get("currency") or "SGD"`).
- **(b)** `transmission_service._execute_transmission` dispatches the VALIDATOR by document type exactly as it already dispatches the GENERATOR: `validate_credit_note_xml` for SALES_CREDIT_NOTE, `validate_invoice_xml` otherwise (the old unconditional Step-3 call retired — it would have overwritten the type-aware result).
- **(c)** `ubl-CreditNote.xsd` corrected to the true UBL 2.1 CreditNote contract: `targetNamespace`/default xmlns → `CreditNote-2`; the line element `InvoiceLine` → `CreditNoteLine` (type renamed `CreditNoteLineType`); `InvoicedQuantity` → `CreditedQuantity`; the annotation version bumped with the correction noted. The element ORDER in the sequence matches what the generator emits (header, DueDate, parties, payment terms, tax total, monetary total, lines).
- **(d — discovered)** `ubl-Invoice.xsd` restructured into the same three-namespace shape (the invoice path was equally decorative); both common schemas extracted; both root schemas now validate the generator's own output (pinned by the invoice-side + credit-note-side acceptance gates + the strengthened existing specs).

### Medium

**BE-P34-M1 — the ISO-4217 currency-input truth: every currency input accepts out-of-vocabulary codes.** The five input surfaces (org create `base_currency`, org PATCH `base_currency`, bank-account create `currency`, payment receive `currency`, payment make `currency`) validate only string length — a typo like "XYZ"/"SGE" (or "US" on the create path, which lacks `min_length`) reaches the database and then propagates into the P33 currency-truth surfaces (the reports denomination, the Peppol currencyIDs, the PDF). **Fix:** a NEW shared module `common/currency.py` — `ISO_4217_ACTIVE_CODES` (a frozenset of the active ISO-4217 codes, excluding the placeholder `XXX`/testing `XTS` codes — the documented decision) + `normalize_currency_code(code) -> str | None` (strip, upper-case, membership check). The five surfaces call it in their field-level validators and raise the typed 400 field error on `None`; the accepted value is the NORMALISED code. The org create field additionally gains `min_length=3` (the "US" hole).

## 6. Open decisions (resolved with judgment)

- **True UBL 2.1 CreditNote shape (CreditNoteLine/CreditedQuantity), and the XSD corrected to match — not the generator bent to the XSD:** the repo XSDs are custom simplifications ("LedgerSG PINT-SG Compliant", version 1.1.0) of the OASIS originals; the documents this path transmits face the REAL Peppol network, where `cac:CreditNoteLine` + `cbc:CreditedQuantity` is the required shape and `InvoiceLine` inside a CreditNote is rejected. The XSD's Invoice-2 namespace was a copy-paste artefact of its Invoice sibling (the generator was already right). Fixing the artefact to mirror the real contract is the honest direction; the new InvoiceLine-rejection gate pins it.
- **The transmission dispatch mirrors the generator dispatch (the same if/else):** the minimal, symmetric fix at the existing seam — no validator-interface redesign.
- **The ISO-4217 allowlist = the active codes, minus `XXX` (no-currency) and `XTS` (testing):** the placeholder codes are valid ISO-4217 but carry no business meaning for an accounting platform; excluding them is the documented decision. Case-insensitive with normalisation to upper (the existing validators already upper-cased; a lower-case "usd" is a valid code, not garbage). The list lives in ONE module (`common/currency.py`) — a frozenset, O(1) membership, no dependency.
- **Field-level validators (not a ChoiceField):** a ChoiceField would change the API shape (the DRF choice metadata + the error body) and reject the case-normalisation the existing contract implies; the `validate_<field>` methods keep the established 400 field-error shape (`{"currency": ["..."]}`) while adding the vocabulary check. The org-create field additionally gains `min_length=3` (the "US" hole — a length truth, not a vocabulary truth).
- **No new e2e spec:** the credit-note truth is XML-level (pinned by the new backend specs + the strengthened existing spec); the ISO-4217 truth is a 400-contract (pinned by the new backend spec). The browser surfaces render whatever the API sends. The live re-verification covers the byte-stability claim.
- **The Schematron axis is registered, not fixed:** wiring the .sch is a business-rule layer beyond this sprint's structural truth; the XSD + the generator now agree, and the Schematron placeholder is honest about its emptiness.
- **The UP batch / E501 + format axis / N818 / mypy gate stay out (again):** the registered preconditions are unchanged.
